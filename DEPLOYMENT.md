# Fuel on Go Deployment

## Verified Architecture

- **Android client:** Expo / React Native, SDK 54, TypeScript. The app sends authenticated API requests to the Express backend and stores its session with Expo SecureStore.
- **Web client:** Next.js 16 / React 19 in `frontend/`. Some pages call Supabase directly; other code uses the API client. It is a separate deployment and is not deployed by the Railway backend service.
- **Active API:** Node.js, Express 5, CommonJS. Railway's service root must be `/backend`; `npm start` runs `src/index.js`.
- **Database:** Supabase-hosted PostgreSQL. The active backend accesses it through `@supabase/supabase-js` with a server-only service key. Do not use `src/server.js` for this deployment: that is a separate legacy MongoDB entry point and is not the `npm start` target.
- **Files:** The active Express entry point does not serve static files or accept file uploads. QR codes are generated by the API; no persistent local upload directory is required.
- **Realtime:** The active `src/index.js` does not attach the Socket.IO server. Do not assume Socket.IO is deployed by this service.

The Supabase project already has the app's tables and data. The `email` and `expo_push_token` user columns were added with an idempotent migration. Do not run seed scripts or reset the database as part of deployment.

## Railway Service

Create or link a Railway service for this repository, set its **Root Directory** to `/backend`, and use the checked-in `backend/railway.toml` configuration.

- **Build command:** `npm install` (or `npm ci` when using the committed lockfile)
- **Start command:** `npm start`
- **Entry point:** `src/index.js`
- **Port:** Railway injects `PORT`; the server falls back to `3000` locally.
- **Binding:** The Express listener binds to `0.0.0.0`.
- **Health path:** `/api/health` (also `/health`). The current health handler checks process liveness only, not database connectivity.
- **Readiness path:** `/ready` performs a read-only Supabase query and returns `503` if the database is unavailable.
- **CORS:** Native mobile requests with no `Origin` are allowed. Set `CORS_ORIGINS` to comma-separated exact web origins; localhost origins are allowed only outside production.
- **HTTPS:** Generate a Railway public domain after deployment. Use that HTTPS origin for clients.

The current `railway.toml` uses Nixpacks and `npm start`; no Dockerfile is required. There is no automatic schema migration or database reset at server startup.

## Backend Variables

Set these in Railway's service variables. Never commit secret values.

| Variable | Required | Purpose |
| --- | --- | --- |
| `SUPABASE_URL` | Yes | Supabase project URL used by the server. |
| `SUPABASE_SERVICE_KEY` | Yes | Server-only Supabase service key. Never expose it to web or mobile clients. |
| `JWT_SECRET` | Yes in production | At least 32 characters; signs API session tokens. |
| `PORT` | Supplied by Railway | HTTP listen port. |
| `NODE_ENV` | Set to `production` | Enables production auth protections. |
| `CORS_ORIGINS` | For browser clients | Comma-separated exact frontend origins, without trailing slashes. |
| `OTP_MODE` | Optional, non-production only | `dev` enables the development OTP; production disables the demo flow regardless of this value. |

`OTP_MODE` does not configure an SMS provider. Production phone OTP is deliberately rejected until an actual provider is implemented and configured. The current development OTP is not suitable for production. Do not set a development OTP mode in Railway.

The checked-in `backend/.env.example` lists the backend variables. `MONGODB_URI` belongs only to the unused legacy `src/server.js` path and is not required by `npm start`. `SUPABASE_ANON_KEY`, `FAST2SMS_API_KEY`, `FRONTEND_URL`, and upload-storage settings are not read by the active entry point.

## Database and Authentication

The active backend uses Supabase Postgres tables including `users`, `pumps`, `slots`, and `bookings`; `pump_availability` is a view. Schema changes belong in Supabase migrations and must be checked against the current production schema before application. Railway startup does not apply migrations or seeds.

Production security hardening applied to the linked Supabase project: `pump_availability` uses `security_invoker=true`; `book_slot`, `cancel_booking`, `checkin_booking`, `generate_daily_slots`, and `mark_no_shows` are executable by `service_role` only; all six database functions flagged by the advisor have an empty pinned `search_path`. These changes were applied through the authenticated Supabase MCP; the Supabase CLI is not available here to generate a local timestamped migration file, so reproduce them in source control before provisioning another environment.

The API authenticates users with JWT bearer tokens and uses the Supabase service key for database operations. The current repository has no production SMS delivery implementation. Registration and OTP-send endpoints therefore return `503` in production instead of exposing the development OTP. Configure and implement a real phone verification provider before enabling production registration/login.

## Android API Configuration

All Android API requests use `EXPO_PUBLIC_API_URL`, centralized by `mobile/src/config/constants.ts` and consumed by `mobile/src/config/api.ts` and session rehydration. The verified production value is:

```text
EXPO_PUBLIC_API_URL=https://generous-elegance-production-33ae.up.railway.app/api
```

Set the value in the EAS project's production environment and local `mobile/.env.local`. Also set `EXPO_PUBLIC_SUPABASE_ANON_KEY` in the EAS production environment; the app fails fast if either required client variable is missing. Do not put service keys or Railway tokens in the APK. Android declares network access in `mobile/app.json`; app traffic must use HTTPS in production.

## APK Build

The app is Expo / React Native, not Flutter or a checked-in native Gradle project. `mobile/eas.json` defines APK output for `preview` and `production`.

```powershell
Set-Location mobile
npx eas-cli login
npx eas-cli build --platform android --profile production
```

EAS requires an Expo account login. The verified production APK is `mobile/builds/fuel-on-go-production.apk`. A Metro JavaScript export is not an installable APK.

## Local Development

Backend:

```powershell
Set-Location backend
npm ci
npm start
```

Provide `SUPABASE_URL` and `SUPABASE_SERVICE_KEY` locally. Use a non-production `JWT_SECRET` and development-only OTP mode only in a private local environment.

`npm start` starts the scheduled jobs immediately. They can mark eligible bookings as no-shows and generate next-day slots in the configured database; do not point a local instance at production unless that behavior is intended.

Android:

```powershell
Set-Location mobile
npm ci
npx expo start
```

Set `EXPO_PUBLIC_API_URL` in `mobile/.env.local` to a backend reachable from the device. A phone cannot reach the development computer through `localhost`; use a reachable LAN address or a tunnel.

Web:

```powershell
Set-Location frontend
npm ci
npm run dev
```

The web client has its own `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_SUPABASE_URL`, and `NEXT_PUBLIC_SUPABASE_ANON_KEY` configuration. Review its direct Supabase access and RLS policies separately before publishing the web app.

For local web development, set `NEXT_PUBLIC_API_URL` to `http://localhost:3000/api` and set the Supabase URL/publishable key in the ignored `frontend/.env.local`. For production, set those same variable names in the frontend host's environment and use the verified Railway HTTPS API URL.

## Remaining Limitations

- APK installation on an emulator/device was not tested because Android SDK/ADB is unavailable in this environment.
- Production OTP/SMS delivery is not implemented; production auth endpoints fail closed.
- Supabase security advisor now reports only leaked-password protection disabled. Performance advisories remain for RLS policy initialization and an unindexed pump owner foreign key.

The nearby-pumps API was tested read-only. Authentication returned the expected 401 without a token; full registration/login and booking flows were not exercised because production OTP delivery is not configured.
